# 08 路线图与验收标准

原则：**每个阶段结束都能真实跑通一条「从 JSON 到发布」的链路**，不做半成品大而全。阶段之间不允许跳过验收。

## Phase 0：前置准备（你 + 1 天，可与 Phase 1 并行启动）

| 事项 | 完成标准 |
|---|---|
| 验证 API 上传能否公开（`06` §1.1） | 有结论：能公开 / 被锁私享 |
| 提交 API 审计与配额扩展（如需） | 已提交，保存申请编号 |
| OAuth 同意屏幕改为正式版 | 授权页无「测试」标记 |
| 开通：Cloudflare R2、Neon/Supabase、GitHub 私有仓库、LLM Key | 4 个账号可用 |
| 盘点现有渲染器 | 列出已有机制与代码位置，映射到 `05` §2.1 |
| 清点旧视频治理清单 | 15 条旧视频改为不公开（可先手动） |

## Phase 1：MVP「一个频道，导入 → 渲染 → 审核 → 发布」（约 2–3 周）

**范围**
- 登录、频道连接（OAuth）、频道档案（最小字段）；
- `videospec/1` zod schema + JSON Schema 导出 + 导入 API/页面（`dry_run`、错误清单）；
- 模板注册表 + **2 个模板**：`melody-bounce`、`ball-sort`（确定性渲染）；
- 公版旋律库：导入脚本 + ≥ 20 首（先以 Mutopia/自录入为准）+ 程序生成旋律器；
- 渲染 Worker：Docker 镜像 + GitHub Actions workflow + Worker 协议（`04` §3.3）；
- 自动 QA（规则类）+ 差异度守卫**告警模式**；
- 审核队列（L0 全手动）；
- 发布：上传 private + publishAt + 首评；配额台账；若审计未过则启用「半手动发布包」；
- 同步远端视频；导入 Studio CSV；单视频 24h/48h 指标快照；
- 任务系统 + tick + R2 清理；
- 基础监控页：任务/失败/配额。

**验收（全部满足才算通过）**
1. 导入 `07` §5 的两个示例 → 各自渲染成功，1080×1920、30fps、−14±1 LUFS、时长与 Spec 一致；
2. **确定性**：同一 Spec 连续渲染两次，视频逐帧哈希一致（允许容器差异时，以帧像素哈希对比，容差为 0）；
3. 导入故意写错的 JSON，返回带 JSON 路径的结构化错误；
4. 审核通过 → 上传成功 → 到点公开（或半手动包流程走通）；
5. 同一任务重复触发 / 网络中断重试，**不会产生重复视频**（测试：强制第一次上传在 90% 处失败）；
6. 渲染失败有分类原因，可一键重试；
7. 24h 后能看到该视频的指标快照；
8. 密钥不出现在日志和前端 bundle；
9. 提供 `README` 说明本地启动、环境变量、如何换 Worker 运行环境。

## Phase 2：多频道 + 规划器 + 差异度强制 + 自动补货（约 2–3 周）

**范围**
- 多频道硬隔离（数据/存储/配额/UI 切换器）；
- 差异度守卫从「告警」升级「阻断」（用 Phase 1 的数据先校准阈值）；
- 排期规划器 + 日历（拖动、自动选槽、60/30/10 配比）；
- AI 适配器（T1/T2/T3 三档）+ 成本台账 + 预算熔断；
- 自动补货：水位线 → 采样组合 → AI 写 Spec → 校验 → 渲染；
- `ideabatch` 导入与「展开为 Spec」；
- 半自动审核（L1）与信任等级升降；
- 视频管理：批量改隐私、改元数据、删除（二次确认+审计）；
- 通知：每日摘要（邮件）。

**验收**
1. 两个频道并行跑，任何查询/任务/存储路径都无法跨频道读到对方数据（有自动化测试）；
2. 人为制造「同机制连续 3 条」→ 守卫阻断并提示可改的轴；
3. 池子低于水位线时 10 分钟内自动补货，AI 成本被记账；预算耗尽时补货停止并告警，不影响已排期发布；
4. 一个频道凭据失效，只暂停该频道，另一个照常发布；
5. 删除视频必须二次确认且写审计日志；
6. 配额不足时任务顺延，次日 PT 午夜后自动恢复。

## Phase 3：数据闭环 + 趋势 + 评论（约 2–3 周）

**范围**
- 数据看板：按模板/旋律/钩子/标题模式聚合；订阅转化；继续观看估算；留存曲线；
- 记分牌 + Thompson Sampling + 周报（T3 一次/周）；
- 参考频道库（RSS + `videos.list`，离群爆款榜）；
- 趋势信号库 + `trendimport` + 选题建议（生成 `ideabatch`）；
- 评论中心：同步、AI 起草、人工确认回复、隐藏垃圾；
- 视觉 AI 抽检（T2）；
- 「做下一集」爆款复用；
- Telegram 审核（可选）。

**验收**
1. 任意视频能看到「72 小时评分 + 标签（breakout/solid/flop）+ 归因轴」；
2. 参考频道库对 ≥ 10 个频道每天更新，**日耗配额 ≤ 100 单位**；
3. 评论回复流程：同步 → 起草 → 确认 → 发送，全程 ≤ 3 次点击；
4. 记分牌周报包含「下周建议的 60/30/10 配比」，并被规划器采用；
5. 视觉抽检对故意放入的「文字被遮挡」测试视频能报错。

## Phase 4：自动化放开与扩展（持续）

- L2 全自动（抽检 20%）、事后撤回触发降级；
- 新模板：`pendulum-wave`、`marble-run`、`rings-escape`、`orbit-sync`；
- 长视频合集生成器（8–10 分钟，用于观看时长与 YPP 小时数路径）；
- TikTok / Instagram 发布（先评估各自 API 审核）；
- 多用户/团队权限。

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| API 未审计 → 上传被锁私享 | 中 | 高（阻断全自动） | Phase 0 验证；半手动发布包；尽早提交审计 |
| 默认配额只够 ~4–6 条/天（多频道合计） | 高 | 中 | 先单频道；申请配额扩展；日历显示配额 |
| 内容被判「重复/批量生产」 | 中 | 高（影响 YPP） | 差异度守卫 + 系列规范 + 频道品牌识别 + 人工审核记录 |
| 公版旋律被 Content ID 误认领 | 低-中 | 中 | 记录与替换流程；偏向程序生成原创旋律 |
| 免费资源额度变化/封号 | 中 | 中 | 存储/渲染/AI 都是适配器；数据可导出；Worker 协议通用 |
| 模板质量不够（钩子差） | 高 | 高 | 钩子 QA；探索配额；以数据迭代模板 |
| 范围蔓延 | 高 | 中 | 严格按阶段验收；`03` 4.10 排除清单 |
| 平台政策/口径再变（如播放量口径） | 中 | 中 | 指标层抽象；以 `engagedViews` 为准 |
