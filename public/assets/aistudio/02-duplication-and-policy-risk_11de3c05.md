# 02 「视频重复会不会有问题」与防重复机制

## 1. 简短回答

**会有问题，但要分清三个层面，它们后果不同：**

| 层面 | 谁判定 | 后果 | 你现在的状态 |
|---|---|---|---|
| ① 政策层：`inauthentic content`（原 repetitious content，2025-07-15 更名） | YouTube 人工 + 自动，按**整个频道**评估 | 不能加入 YPP / 被移出 YPP（只影响变现，不是封号） | **有风险**：10 天发 9 条同一机制，且有同标题重复 |
| ② 推荐层：相似内容聚类 + 观众疲劳 | 推荐系统 | 同类视频不叠加，观众看过类似的更容易划走 | 目前没有表现出惩罚（重复版播放与同系列持平），但也没有复利 |
| ③ 观众层：重复感 | 观众 | 回头客不涨、订阅不涨 | **已发生**：回访观看者仅 0.19%、订阅 0.65/千 |

**同模板 ≠ 违规。** 「Will the Ball Escape」品类有成千上万条同模板视频。YouTube 政策关注的是：**大批量、几乎无变化、没有创作者独特价值**。同一机制但规则、场景、旋律有实质变化是允许的；换颜色和标题不算实质变化。

> 重要事实：YouTube 官方说明 2025-07 的更名是「澄清」，并非新规；该政策历来作用于整个频道。2026 年的资料显示审查在加强（第三方汇总，官方没公布判定阈值）。**没有任何人能给出确切的「重复多少条会被处罚」，所以我们的做法是留足安全余量 + 系统化地保证差异。**

## 2. 平台实际能「看到」哪些维度的相同

我们设计差异度时要覆盖平台能识别的所有维度，而不仅是肉眼维度：

| 维度 | 平台怎么看 | 「假差异」（无效） | 「真差异」（有效） |
|---|---|---|---|
| 视觉 | 帧级特征/感知哈希、场景布局 | 换配色、换背景色 | 换场地形状、规则、物体数量与运动方式、镜头语言 |
| 音频 | 音频指纹（Content ID 对旋律/录音） | 换音色、变调 | 换曲目/换旋律、换节奏结构 |
| 结构 | 时间线结构（钩子—升级—结尾）的重复 | 只改文字 | 改叙事结构、升级曲线、结尾方式 |
| 文本 | 标题/描述/标签的相似度 | 加 emoji、加 #shorts | 换句式、换悬念类型 |
| 行为 | 观众的观看模式 | — | 由以上真实差异自然带来 |
| 元信息 | 上传模式、时间、账号集群 | — | 不同频道用不同节奏与风格 |

## 3. 从你的数据看到的具体问题

- 同标题重复：`16 Balls, 4 Bins... Can They Sort Themselves?`（11/4、11/9），`16 Balls, 4 Bins 🌈 Satisfying Ball Sort`（11/4、11/10）。
- 「16 Balls, 4 Bins」标题骨架共出现 9 次（后缀分别是 Gates、Spiral Machine、1 Moving Gate、12 Seconds…），本质是同一机制的参数变化。
- 这些视频表现稳定在 ~1,000 播放：**没被抑制，但也没被放大**。

## 4. 防重复机制（Novelty Guard）——开发必须实现

### 4.1 差异度「轴」（axes）

每条 VideoSpec 必须声明它在这些轴上的取值（`fingerprint_hints.axes`，见 `07`）：

| 轴 | 例子 | 类别 |
|---|---|---|
| `mechanic` | ball-sort / melody-bounce / pendulum-wave / sort-sound / pi-collision | 结构 |
| `arena` | circle / polygon / ellipse / spiral / funnel / open-field | 结构 |
| `rule` | grow-on-bounce / split / gravity-flip / shrinking-wall | 结构 |
| `music_piece` | `pd:canon-in-d` / `gen:pentatonic-seed-8841` | 音频 |
| `instrument` | marimba / glockenspiel / kalimba / pluck | 音频（弱） |
| `palette_family` | neon / pastel / mono / warm | 视觉（弱） |
| `hook_style` | prediction / escalation / mystery / countdown / contrast | 概念 |
| `title_pattern` | question / number-contrast / challenge / statement | 文本 |
| `ending` | loop / reveal / cut | 结构 |

「弱」轴（乐器、配色）不计入差异度，只做装饰。

### 4.2 硬规则（默认值，可按频道配置）

对**同一频道**，以发布排期（含待发布队列）为窗口：

1. **同 `mechanic` 在近 7 天最多 2 条；近 30 天占比 ≤ 30%。**
2. **相邻两条已发布/待发布视频，在「结构类+音频类+概念类」轴上至少 2 个轴不同。**
3. **同一 `music_piece`：14 天内最多 1 次；同一曲目的第二次出场必须换 `mechanic` 或 `rule`。**
4. **同一 `title_pattern` + 相同前 3 个单词：7 天内最多 1 次。**
5. **禁止同标题（忽略大小写、emoji、#标签后）重复发布；禁止同一渲染文件重复上传。**
6. **同一频道日发布量上限**（默认 3，可配）；新增频道在前 14 天上限 2。
7. **跨频道**：不同频道禁止发布相同 `mechanic + music_piece + hook_style` 组合；跨频道素材文件哈希不得相同。
8. 系列（series）是例外也是规则：**系列内的集数覆盖规则 1 的「7 天最多 2 条」**，同系列 7 天最多 3 集；该机制在 30 天内的占比上限放宽到 40%。但每集必须有**可说清的实质变化**（`concept.novelty_notes` 必填，并且与上一集相比 ≥ 2 个结构/音频/概念轴不同）。

### 4.3 相似度检测（自动，在渲染后做）

| 检测 | 方法 | 阈值（初值，需标定） | 动作 |
|---|---|---|---|
| 画面相似 | 抽 8 帧→感知哈希（pHash）/ 缩略特征，与近 60 天本频道视频比对 | 平均汉明距离低于阈值 | 标记 `near_duplicate_visual` |
| 旋律相似 | 从音符事件序列（我们自己生成，无需音频分析）比对：音程序列编辑距离 | 相似度 > 0.8 | 标记 `near_duplicate_melody` |
| 标题/文案相似 | 文本嵌入或 3-gram Jaccard | > 0.7 | 标记 `near_duplicate_text` |
| 渲染文件 | 文件 SHA-256 与近似哈希 | 完全相同 | 直接阻断 |

结果汇总成 **Novelty Score（0–100）**。< 60 阻断发布并给出「建议改哪些轴」；60–75 需人工确认；> 75 通过。**阈值先宽后紧：上线前两周只告警不阻断，用你的真实数据校准后再阻断。**

### 4.4 「同一创意复用」的正确做法

如果某条视频是爆款，想复用：
- 不要重发；做「第 2 集」：换规则/曲目/场景，保留**观众喜欢的核心**（例如「旋律逐步加速」这个钩子），标题用同一系列但不同句式；
- 系统用「爆款复用建议」生成 3 个候选 Spec，仍然要过差异度守卫。

## 5. 频道级的「真实性」要点（YPP 审核会看）

YouTube 说的不是「禁止程序生成」，而是缺乏「创作者原创价值」。给每个频道配置并在视频里体现：
1. 一致的**品牌识别**：固定的视觉语言、固定的片头 0.5 秒标识、系列命名；
2. **原创素材**：画面由自己的代码渲染，旋律是公版曲目的**自己演奏编配**或原创；
3. **内容价值**：每条有明确钩子和「看完得到什么」；
4. **人工参与证据**：审核记录、手写的系列设定与频道说明（工作台保存审核日志）；
5. 不使用他人素材；趋势只用于选题，不复制别人的视频（第三方资料：照搬热门会被判低原创）。

## 6. 对其他风险的补充

- **合成/改动内容披露**：YouTube 要求对「逼真的合成内容」披露；抽象物理动画一般不需要。VideoSpec 保留 `publish.contains_synthetic_media`（默认 false），如果以后加入 AI 生成的写实素材必须设为 true。
- **Content ID**：公版曲目的「自己合成的演奏」一般不会被认领，但偶尔会有他人注册的录音误伤。工作台要有「版权声明处理手册」：记录被认领视频、改用别的旋律重发（走「第 2 版」流程，不是原样重发）。
- **不要通过创建多个 Google Cloud 项目绕过配额**：API 服务条款禁止；走审计申请（见 `06`）。
