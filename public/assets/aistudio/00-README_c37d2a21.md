# 视频工作台（Shorts Studio）文档总览

> 状态：方案讨论稿 v1（尚未写代码）。本目录是项目的唯一事实来源（source of truth）。
> 如果文档和对话/Prompt 冲突，以本目录为准；本目录内部冲突，以本页「决策记录」为准。

## 1. 一句话目标

做一个**多频道的 YouTube Shorts 自动化工作台**：在一个页面里完成「素材/创意生成 → 视频渲染 → 审核 → 定时发布 → 数据回流 → 迭代」，核心指标是**频道订阅数和播放量**，不是产量。

## 3. 决策记录（我替你做的推荐决策，有异议再改）

| # | 决策 | 理由（一句话） |
|---|---|---|
| D1 | 第一阶段只做 **YouTube Shorts**，TikTok/IG 发布放到后期，但趋势数据可以参考它们 | YouTube API 最完整；你的数据全是 YouTube |
| D2 | 控制面用现有脚手架：**Next.js(App Router) + Postgres + Drizzle**；生产库用 Neon/Supabase 免费 Postgres，对象存储用 **Cloudflare R2** | 脚手架已是 Postgres；换 D1(SQLite) 要重写 schema，收益小 |
| D3 | 渲染是**独立的无状态 CPU Worker**（容器化），MVP 用 **GitHub Actions** 跑，后续可换 Oracle 免费 VM / 自己电脑 / Cloud Run Jobs | 物理模拟类视频不需要 GPU；Worker 协议统一，可随时换跑的地方 |
| D4 | 配乐只用**公版曲目（自合成演奏）+ 程序生成原创音乐 + CC0 音效**；不用流行/热门歌曲 | 避免 Content ID/版权；且「碰撞触发音符」本身就是你的特色 |
| D5 | AI 分三档：便宜模型批量出 JSON、中档视觉模型做抽检、顶级模型只做每周复盘/写新模板。**不把 AI 视频生成放进主流程** | 成本可控；你的优势是确定性的代码动画 |
| D6 | **VideoSpec JSON 是唯一的内容入口**：AI 生成、人工编写、趋势机器人生成的内容，全都落成同一种 JSON 再导入 | 解耦「生成创意」和「渲染发布」 |
| D7 | 审核分三档：全手动 → 半自动（自动检查通过 + 超时自动过）→ 全自动，用「信任等级」逐步放开 | 先稳后快，防止翻车 |
| D8 | **多频道硬隔离**：所有业务表都带 `channel_id`，对象存储按频道分前缀，素材/模板/配乐默认不跨频道共用 | 避免被平台判定为矩阵号搬运，也避免互相污染 |
| D9 | **差异度守卫（Novelty Guard）是发布前的强制关卡**，不是可选功能 | 见 `02` |
| D10 | 发布策略：审核通过后**上传为 private + `publishAt` 定时**，而不是到点才上传 | 上传配额昂贵（1600 单位/次），提前上传可平滑配额、降低到点失败风险 |
| D11 | UI 中文，代码/数据库字段/JSON 键英文，视频内容语言按频道配置（当前频道为英文） | 你用中文操作；观众是英文 |
| D12 | **先申请 YouTube API 审计/配额扩展**（关键路径） | 未审计的 API 项目上传的视频会被锁成私享，见 `06` |

## 4. 你需要在开发开始前做的前置事项（不是提问，是 Checklist）

1. 确认 Google Cloud 项目：OAuth 同意屏幕**必须是「正式版(In production)」**，如果还在「测试」状态，刷新令牌 7 天过期。
2. 确认该项目是否已通过 YouTube API **合规审计**；没有就立刻提交（`06` 里写了怎么办、没通过前的降级方案）。
3. 准备账号：Cloudflare(R2)、Neon 或 Supabase、GitHub（私有仓库跑渲染）、一个 LLM API Key（OpenAI 兼容协议即可）。
4. 把你现有渲染器的代码仓库（或目录）交给开发 AI，让它盘点已有模板并按 `07` 对齐参数（你说「不纠结以前的东西」，所以只做对齐，不做迁移）。
5. 第 2 个频道的定位先想一个方向（见 `01` 第 7 节的建议），不要和第 1 个频道同题材。

## 5. 重要说明：哪些是事实，哪些是推断

- **事实（已查证，2026 年资料）**：YPP 门槛、上传配额 1600 单位、未审计项目私享限制、Shorts 观看量口径变化、`inauthentic content` 政策、免费层额度。具体来源见各文档。
- **推断/经验**：Shorts 分发的内部阈值（例如「继续观看 ≥ 60%」才扩量）是第三方总结，YouTube 没有官方公布。文档里凡是这类数字都标了「非官方」。
- **未能确认**：你提到的「instabox」我没能确认是哪个服务；文档按「任何免费的无 GPU CPU 运行环境」的通用要求设计，Worker 协议不绑定具体平台。
