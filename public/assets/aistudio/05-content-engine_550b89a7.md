# 05 内容生产引擎

目标：**批量、稳定、长期地生产「平台认为不同」且「观众想看完、想订阅」的视频。**

## 1. 流水线分层

```
L0 信号（趋势 · 参考爆款 · 自家数据 · 运营者输入）
   ↓
L1 创意 Concept：钩子 + 机制 + 回报 + 情绪 + 系列/集数        （ideabatch）
   ↓  代码先抽「轴组合」，AI 只负责写创意细节（§4）
L2 规格 VideoSpec：可直接渲染的完整 JSON                        （specbatch，见 07）
   ↓  校验（zod + 模板 schema）+ 差异度预检
L3 渲染：Worker 确定性渲染 → mp4 / 帧 / 事件 / 指纹
   ↓
L4 QA：规则检查 + 差异度评分 + （P1）视觉 AI 抽检
   ↓
L5 审核 → L6 发布 → L7 数据回流 → 更新 L0
```

## 2. 模板库（Template Library）

模板 = 一个可复用的「视觉机制」，带**参数 schema**、**轴声明**、**示例 Spec**、**版本号**。模板本身由人/编码 AI 写代码，**不由运行时 AI 生成**。

### 2.1 起步模板（按你的数据优先级）

| 模板 key | 机制 | 备注 | 优先级 |
|---|---|---|---|
| `melody-bounce` | 小球在场地内弹跳，每次碰撞触发旋律下一个音；有升级规则（变大/变快/分裂/墙体缩小） | 你的 B 系列 + 品类爆款公式，**第一优先** | P0 |
| `ball-sort` | N 个球通过机关落入 M 个桶并分色 | 你的 A 系列，必须带强差异的机关组合，限频 | P0 |
| `pendulum-wave` | 多摆相位逐渐分离/重合形成图案，配音阶 | D 系列里 40 Pendulums 表现较好 | P1 |
| `sort-sound` | 排序算法可视化 + 每次比较一个音 | C 系列转化为 0，需先改进钩子再决定是否保留 | P1 |
| `collision-count` | 方块碰撞计数（π）类 | 单条订阅 3，值得保留，但属于慢热 | P1 |
| `orbit-sync` | 多轨道重合 | 80 秒长版适合做「观看时长型」 | P2 |
| `rings-escape` | 球逃出可再生的多层圆环（品类标准机制） | 品类已饱和，需要新规则才有价值 | P2 |
| `marble-run` | 弹珠机关 + 乐器 | 新增，视觉差异大 | P2 |

> 开发 AI 先盘点你已有的渲染器，把已有机制按上表映射；**不强求迁移全部**，先迁移 `melody-bounce` 与 `ball-sort` 即可跑通闭环。

### 2.2 模板接口约定
每个模板导出：
- `key`, `version(semver)`；
- `paramsSchema`（JSON Schema）与 `defaults`；
- `axes`：该模板可取的 `arena/rule/ending` 等枚举；
- `estimateCost(spec)`：预估渲染秒数；
- `render(spec, ctx) → {frames(stream), events[], durationSec}`；
- `examples[]`。
- 确定性：所有随机来源来自 `spec.scene.seed`；禁止读取系统时间/随机数。

## 3. 钩子、循环与互动设计（直接对应诊断 F6/F8）

### 3.1 钩子（第 0–1.5 秒）
- 第 0 帧必须已经有「运动 + 一个可识别的对象」，禁止黑场/淡入；
- 第 0–0.5 秒必须出现一个声音事件（碰撞音/起音）；
- 文字钩子（≤ 6 个词，位于 Shorts 安全区内）；
- 钩子类型（`hook_style`）：
  - `prediction`「Which bin fills first?」——让人想等答案；
  - `escalation`「It gets faster every bounce」；
  - `mystery`「Can you name this song?」（旋律球专用，强烈推荐）；
  - `countdown`「10 seconds. 16 balls.」；
  - `contrast`「1 ball vs 1000 balls」。
- QA 自动检查：首帧非空、前 1.5 秒画面差异度 > 阈值、前 0.5 秒音频能量 > 阈值。

### 3.2 循环
- 模板内置 `loop.mode`：`visual-return`（最后一帧回到第一帧状态）、`audio-return`（旋律最后一个音接回第一个音）、`none`；
- 默认 `loop.enabled = true`，时长 15–35 秒为主；每 5 条里安排 1 条 45–80 秒的「观看时长型」。

### 3.3 互动
- `publish.first_comment`：发布后由系统以频道身份发一条提问式首评（例如「Did you get it before the 10th note? 👇」）；**YouTube API 不支持置顶**，置顶需要在 Studio 手动点一下（审核页给出提示与链接）；
- 标题悬念类型与钩子匹配；
- 评论中心里把「对首评的回复」优先显示，鼓励运营者回复（回复本身是互动信号）。

## 4. 差异化系统（对应 `02`）

### 4.1 核心原则：**代码选组合，AI 写风味**
大模型天然会重复自己（mode collapse）。所以：
1. 代码从 **轴空间** 中采样出「候选组合」，先过差异度守卫（对近 60 天历史和待发布队列），**只把通过的组合交给 AI**；
2. AI 的任务是：给这个组合写标题、钩子文案、首评、系列命名、详细参数；
3. 已用过的组合/标题骨架作为**禁用清单**放进提示词。

### 4.2 轴空间（示例，由模板声明，运营者可扩展）
| 轴 | 取值示例 | 可采样规模 |
|---|---|---|
| mechanic | 8 个模板 | 8 |
| arena | circle / hexagon / triangle / ellipse / spiral / funnel / stairs / open | 8 |
| rule | grow / split / gravity-flip / shrink-wall / speed-up / trail-fade / portal | 7 |
| music_piece | 公版库 ≥ 60 首 + 程序生成无限 | 60+ |
| hook_style | 5 | 5 |
| ending | loop / reveal / cut | 3 |
理论组合 ≥ 8×8×7×60×5×3 ≈ 50 万，**真正稀缺的不是组合数，而是「观众能感知的实质差异」**，所以按 `02` 的硬规则限频，而不是穷举。

### 4.3 内容配比（每个频道每周）
- **60% 主打**：近 30 天综合评分前 30% 的机制+钩子，但组合必须是新的；
- **30% 相邻**：在主打基础上换 1–2 个结构轴；
- **10% 探索**：全新机制或全新钩子（含「讲解类」的再验证，见诊断 F4）。

## 5. 配乐与音频

### 5.1 原则
1. **音乐 = 画面的一部分**：由模拟事件触发（每次碰撞一个音符/音色），而不是后期贴一首歌；
2. **只用我们拥有或公版的旋律**：不用流行/影视/热门榜单歌曲（作曲版权仍在，Content ID 可按旋律认领，**哪怕你自己合成演奏**）；
3. 每首旋律入库必须记录：`composer`、`death_year`、`source_url`、`license`、`notes`；入库规则：作曲者逝世 ≥ 70 年（保守起见：逝世年份 ≤ 1950）或传统民歌或 CC0/自创；
4. MIDI 文件本身也可能有「整理者版权」：只使用 Mutopia Project（公版/CC）、明确 CC0 的来源，或自己按乐谱录入；IMSLP 逐份看许可。

### 5.2 旋律来源
| 来源 | 内容 | 用途 |
|---|---|---|
| 公版曲目库（初始 ≥ 60 首） | 卡农（Pachelbel）、欢乐颂、致爱丽丝、山魔王（Grieg）、小夜曲、土耳其进行曲、月光、天鹅湖、威廉退尔序曲、绿袖子、各国民歌… | `melody-bounce` 的主要内容，「猜曲名」钩子 |
| 程序生成旋律 | 五声/调式音阶 + 马尔可夫/和弦进行 + 欧几里得节奏，种子可复现 | 无限供给原创旋律；每频道有自己的「调式/节奏风格」 |
| 音效 | Freesound 的 CC0 音效、自己合成的打击/按键声 | 碰撞音色 |
| 合成器 | numpy 合成（FM/Karplus-Strong 弦/木琴/马林巴）或 FluidSynth + CC0 SoundFont | 无外部依赖，Worker 内完成 |

不推荐：TikTok 热门音频（YouTube 上不可用）；Pixabay 音乐（有被 Content ID 误认领的报告）；YouTube Audio Library（无 API，需手动，且很多视频在用，识别度反而低）。

### 5.3 旋律数据格式
`melody/1` JSON（见 `07`）：音符事件 `{beat, pitch(MIDI), dur_beats, velocity}`，加调号、速度。支持让 AI 生成**原创旋律 JSON**（可校验：音域、时值总和、重复度）。**不要让 AI 凭记忆写公版名曲的音符**（经常错），公版曲用 MIDI/乐谱导入。

### 5.4 混音标准
- 目标响度 −14 LUFS（±1），真峰值 ≤ −1 dBTP；
- 开头 0–0.5 秒必须有起音；结尾淡出 ≤ 0.3 秒或直接接回开头（循环）；
- 手机扬声器友好：中频 500Hz–4kHz 要清晰，避免只有超低频；
- 单声道兼容检查。

## 6. 素材的稳定来源（回答「素材从哪来」）

| 来源 | 稳定性 | 成本 | 用法 |
|---|---|---|---|
| ① 程序化生成（模板 × 参数 × 种子） | 无限 | 0 | 主力 |
| ② AI 批量生成 Spec/创意 JSON | 高 | 几乎 0（见 §9） | 补货 |
| ③ 数据驱动（自家爆款、参考频道离群爆款、趋势） | 中 | 低 | 决定生成什么 |
| ④ 旋律库（公版导入 + 程序生成） | 高 | 0 | 配乐 |
| ⑤ 运营者手工 | 低 | 时间 | 特殊创意、第 2 个频道的定位设计 |

**自动补货**：每个频道有「待发布池最少 5 天」的水位线；低于水位 → `generate_specs` 任务 → 采样组合（§4）→ AI 写细节 → 校验 → 渲染。补货失败（AI 超预算/校验连续失败）触发告警，不会静默断供。

## 7. 趋势与参考频道情报（P1）

### 7.1 数据源（务实版）
| 来源 | 方式 | 成本/限制 |
|---|---|---|
| 参考频道 RSS | `https://www.youtube.com/feeds/videos.xml?channel_id=...`（公开、不耗 API 配额） | 免费 |
| 参考视频统计 | `videos.list`（1 单位/最多 50 个 ID） | 极低 |
| YouTube 热门 | `videos.list?chart=mostPopular&regionCode=..&videoCategoryId=..`（1 单位） | 免费；热门榜不区分 Shorts |
| YouTube 关键词搜索 | `search.list`（**100 单位/次**，`videoDuration=short&order=viewCount&publishedAfter=..`） | **每天最多 ≤ 5 次**，避免挤占上传配额 |
| Google Trends | 非官方库或手动导出 | 不稳定，作为辅助 |
| 维基百科浏览量 API | 官方、免费 | 科学/数学话题热度（如 π 日、天文事件） |
| Reddit（r/oddlysatisfying、r/physicsgifs、r/Simulated 等） | 官方 API，注意条款与限频 | 辅助灵感 |
| TikTok Creative Center / Instagram | **没有官方公开 API**；抓取工具（如 Apify 付费）或**手动导出后用 `trendimport` JSON 导入** | 建议先手动，每周一次 |

### 7.2 离群爆款算法（参考频道）
`outlier_ratio = 视频播放 / 该频道最近 30 条的中位数`；`outlier_ratio ≥ 5` 记为爆款。对爆款提取：机制/规则/旋律/标题模式/时长，由 AI 归类到我们的轴，**只作为选题输入，禁止复制画面或标题**。

### 7.3 趋势使用边界
- 趋势用来选「话题/旋律风格/机制」，不用来照搬视频；
- 热门音乐只作为「用户在找什么」的信号（比如某首公版曲突然火了），不能直接使用有版权的曲目。

## 8. 数据回流与学习

### 8.1 评分（72 小时后计算，且播放 ≥ 300 才评分）
```
reward = 0.35·z(继续观看%) + 0.25·z(min(平均观看百分比,150)) + 0.25·z(订阅/千播放) + 0.15·z((分享+评论)/千播放)
```
`z` 为相对**该频道最近 30 条**的稳健标准分（中位数/MAD）。标签：
- `breakout`：播放 ≥ 5× 频道中位数 或 ≥ 10,000；
- `solid`：reward ≥ 0；
- `flop`：播放 < 0.3× 中位数 或 reward < −1。

### 8.2 探索/利用
对 `(mechanic, hook_style)`、`music_piece 风格`、`title_pattern` 维护 Thompson Sampling（高斯），按 §4.3 的 60/30/10 配比抽样；**守卫优先于采样**（采样结果违反差异度就重采样）。
样本量小（每天 3 条）→ 先用粗粒度的轴，不要细分到参数；每周自动生成「记分牌周报」。

### 8.3 Shorts 特有口径
- YouTube Analytics API 有 `views`、`engagedViews`、`averageViewPercentage`、`averageViewDuration`、`audienceWatchRatio`（按 `elapsedVideoTimeRatio` 的留存曲线）；
- Studio 里的「继续观看 %」不一定能从 API 直接取到，**用 `engagedViews / views` 作为估算**（别人的开源实现也这么做），并在 UI 标注「估算」；以 Studio 导出的 CSV 为校准基准；
- 留存曲线用来定位「在第几秒掉量」，驱动钩子/中段优化建议。

## 9. AI 的使用与成本

### 9.1 分档（D5）
| 档位 | 任务 | 模型类型 | 频率 |
|---|---|---|---|
| T1 便宜 | 批量写 Spec/创意 JSON、标题/描述变体、评论回复草稿、趋势归类 | Flash-Lite / DeepSeek 一类（OpenAI 兼容） | 每天 |
| T2 中档视觉 | 对 5 个关键帧 + 标题做视觉抽检（钩子是否清晰、文字是否可读、有无不当内容） | 带视觉的 Flash 一类 | 每条视频 |
| T3 顶级 | 每周复盘报告、新模板/新规则的设计建议、疑难政策判断；**写模板代码交给编码 AI，不在运行时调用** | 当期最强模型 | 每周 1 次，或按需 |

### 9.2 成本估算（量级，价格取 2026-04 资料：Flash-Lite 约 $0.10/$0.40 每百万 token，DeepSeek V3.2 约 $0.28/$0.42）
- 一批 10 条 Spec：输入约 6k + 输出约 8k token → **约 $0.005**；
- 视觉抽检每条约 2–3k token → **< $0.002**；
- 每周顶级复盘：输入 40k + 输出 5k，按 $3/$15 每百万计 → 约 **$0.2/次**；
- **3 个频道 × 每天 3 条 ≈ 270 条/月：全部 AI 成本通常 < $5/月（不含顶级复盘），含复盘 < $10/月**。
- 真正的成本风险是「重试风暴」与「误用顶级模型批量生成」。

### 9.3 成本控制措施
1. 每频道月预算（默认 $5）、全局月预算；`ai_calls` 台账记录每次调用成本；
2. 80% 告警、100% 停止非必要任务（保留渲染/发布）；
3. 严格 JSON schema 输出 + 校验失败最多重试 2 次（带错误信息）；
4. 把历史摘要压缩成固定长度（最近 30 条的轴组合表，而不是全文）；
5. 提示词模板版本化，记录 `prompt_version`；
6. 厂商可切换（`LLM_BASE_URL` + `LLM_MODEL_T1/T2/T3` 三个环境变量）。

### 9.4 不用 AI 的地方
差异度判定、排期、配额、规则检查、评分、渲染——全部是确定性代码。AI 只提供「创意与文案」和「抽检意见」，**没有发布权**（除非信任等级为 L2，并且仍受守卫约束）。

### 9.5 AI 生成视频（Veo/Sora/可灵等）
不进入主流程：成本高、风格不稳定、与频道「代码物理」识别度冲突，且写实合成内容有披露义务。以后若要做长视频 B-roll，作为独立 P2 功能，单独预算。

## 10. QA 检查清单（自动）
| 检查 | 规则 |
|---|---|
| 规格 | 1080×1920（或 1080×1080）；30fps；H.264/AAC；时长 ≤ 180s（推荐 15–60s） |
| 画面 | 首帧非空；无黑帧（>0.3s）；文字在 Shorts UI 安全区内（顶部 ~10%、底部 ~20%、右侧 ~15% 留空） |
| 音频 | 响度 −14±1 LUFS；峰值 ≤ −1dBTP；无 >0.5s 静音；开头 0.5s 有起音 |
| 钩子 | 前 1.5 秒运动量 > 阈值 |
| 循环 | `loop.enabled` 时首尾帧差异 < 阈值 |
| 文本 | 标题 ≤ 100 字符；描述含系列信息；无重复标签 |
| 差异度 | `02` 的 Novelty Score |
| 合规 | 旋律在库内且 license 合规；`contains_synthetic_media` 与素材类型一致 |
